# Проверка интерфейса карты

Локальный headless Edge через существующий CDP, без сборщика и npm-зависимостей.
Сайт и данные не меняются. Скрипт внедряет `ui_probe.js` и локальный
`vendor/axe/axe.min.js` только в проверочный браузер.

## Запуск

Из корня `maap`, в первом терминале:

```powershell
python -m http.server 8765
```

Во втором терминале:

```powershell
python tools/ui_check.py --json
python tools/ui_check.py w=390 out=tools/ui-check-results --json
python tools/ui_check.py --only=targets --json
python tools/ui_check.py --only=axe --json
python tools/ui_check.py --only=scenarios --json
python tools/ui_check.py --only=axe --axe-all --json
```

По умолчанию: 360, 384, 390 × 800 CSS px, DPR 2, mobile/touch.
На каждой ширине восемь состояний и восемь сценариев (всего 48 страниц).
Каждое состояние и сценарий начинается с новой загрузки страницы; localStorage
проверочного профиля очищается, обучение помечается пройденным. История и недавно
открытые внутри одного сценария сохраняются. В обычный профиль Edge скрипт не входит.

`--only=targets` запускает геометрию восьми состояний; `--only=axe` — axe
в тех же состояниях; `--only=scenarios` — только восемь сценариев. Полный запуск
также проверяет axe в конечном состоянии каждого сценария, включая состояние
после неудачного шага. Отсутствующий axe не замалчивается: это ошибка прогона.

`--json` без имени сохраняет `report.json` рядом со снимками; имя можно задать
как `--json tools/report.json`. Без `out=...` создаётся сохраняемая временная
папка, её путь печатается. Скриншот сохраняется в конце каждого состояния и
сценария, при сбое — по возможности в месте сбоя. Снимки не удаляются автоматически.

Нужны штатный Edge, Python, соседние `../phone-bench/cdp.py` и
`../tools/ship-shots/killedge.py`. Порт CDP — 9462, профиль —
`%TEMP%/edgeprofuicheck`. Два экземпляра одновременно не запускать; занятый
порт даёт ошибку. В конце закрывается только проверочный профиль.

## Разделы отчёта

- **Цели / targets:** существующая проверка ≥48×48 CSS px, выхода за экран,
  попадания в центр и четыре края, пересечений целей. Область: панель карты,
  панели окон, шторка, поиск, крестики окон. Текстовые ссылки статей не входят
  в проектное требование 48×48. У каждой цели есть строка, включая `OK`.
- **axe:** по умолчанию теги `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`,
  `wcag22a`, `wcag22aa`. Это доступные автоматические правила WCAG 2.0/2.1/2.2
  уровней A/AA, без `best-practice`. `--axe-all` передаёт запуск без фильтра
  тегов: все включённые по умолчанию правила axe, включая best-practice;
  экспериментальные/отключённые правила библиотеки принудительно не включаются.
  В таблице и JSON: правило, влияние, селектор, пояснение. Нарушение считается
  отдельно для каждого узла правила; повторы на разных экранах сохраняются.
- **Проверить руками:** `axe.incomplete`, отдельно в конце таблицы и в
  `manual_review` JSON. В счёт нарушений не входит. Например, контраст на
  арте/прозрачной подложке может требовать ручной оценки. Версия поставляемого
  axe — 4.10.2, лицензия MPL-2.0 лежит рядом с библиотекой.
- **Сценарии:** журнал шагов в `scenarios[].steps`, итог в таблице. Первый
  неудачный шаг останавливает только свой сценарий; ошибка содержит название
  шага и причину. Остальные сценарии и ширины продолжаются.
- **Ошибки страницы / запуска:** исключения страницы, rejected promises,
  ошибки CDP, подготовки, axe и снимков. Это нарушения/неполный прогон,
  они не превращаются в успешный пустой отчёт.

В JSON прежний массив `states` сохранён; добавлены `scenarios`, `axe` у каждой
проверки, `manual_review`, выбранный `only`, `axe_all`. `complete` отражает
полноту выполнения, а не отсутствие нарушений доступности. Итоговая строка
остаётся `нарушений N`. Код 0 — чистый полный прогон, 1 — нарушения или
неполный прогон, 2 — ошибка аргументов. Отчёт не доказывает полное соответствие WCAG.

## Сценарии и допущения

1. `layers-esc` и `layers-history`: ненулевая прокрутка планшета → статья
   `tt/greyspirit/4tRzyNaVfEQ` → изображение → назад закрывает только изображение →
   ещё назад закрывает окно. Проверяется сохранение позиции планшета (допуск 2 px).
   Статья взята из `steps-photoswipe.json`; если удалена или лишилась картинок,
   сценарий падает явно. Картинка должна открывать штатный PhotoSwipe.
2. `search-return`: поиск → ввод «феном» через CDP → первая строка результата →
   окно → Esc → тот же запрос и ненулевая сохранённая позиция → «Очистить» →
   открытая запись в группе «Недавно открытые» → закрытие поиска кнопкой панели.
   Позиция фиксируется после приведения первого результата в область касания.
   Если результатов мало для прокрутки или первый результат перестал открывать
   окно карты, это явный сбой, а не пропуск проверки.
3. `menu-section`: шторка → «Граф связей» → видимый `#graphLayer`, скрытый
   планшет → шторка над графом → выключить граф → планшет. Затем плитка раздела
   на главной → проверка названия → «‹ Всё» → главная → шторка → Esc.
4. `menu-over-map`: карта → шторка (`#planshet.over-map`, карта видна) →
   касание подложки мимо шторки → закрыта; поиск «феном» → первая запись →
   окно → Esc → результаты → закрыть поиск → карта; шторка → схема корабля →
   `#phenomOverlay.open.map-view`.
5. `view-roundtrip`: карта → Графика → Ноды → граф → планшет → Графика → Карта.
   Граф включается и выключается через шторку и `#menuGraph`, режимы выбираются
   по `[data-view]`. Проверяются режимы, видимость графа и скрытие планшета.
6. `keyboard-panel`: настоящий Tab через CDP по панели Нод. Проверяются
   невидимые/inert цели, границы экрана, перекрытие и `:focus-visible` с outline
   или box-shadow. Обход заканчивается при выходе из панели; обязательные
   кнопки «Феном», «Поиск» и все три режима должны встретиться. Это эвристика видимого кольца;
   его контраст и качество проверить по снимку вручную.
7. `text-200`: `document.documentElement.style.fontSize='200%'`, снимок и
   проверка границ панели и видимых кнопок/ссылок. Это проверка корневого шрифта,
   не полноценная эмуляция Android font scale: размеры, заданные в px, могут
   не увеличиться. Фактический размер корневого шрифта записан в журнал шага.

Кнопки панели, шторки, результатов и изображение нажимаются через
`Input.dispatchTouchEvent` в центр. До касания выполняется hit-test: перекрытый,
inert или находящийся вне экрана элемент даёт ошибку. DOM `.click()` скрипт
не вызывает. Для закрытия шторки касанием подложки выбирается точка, где
hit-test возвращает сам `#planshet`. Только содержимое ленты/шторки явно прокручивается для выбора;
панель перед касанием не подгоняется. Запись для слоёв открывается разрешённым
мостом `window.__mapOpenRecord`. Esc — CDP keyDown/keyUp, браузерный назад —
`history.back()`. Telegram BackButton, клавиатура телефона и safe area здесь
не воспроизводятся. Проверяется локальная страница, не опубликованный сайт.

## Проверки без Edge и передача Claude

```powershell
python -m py_compile tools/ui_check.py tools/ui_scenarios.py
python tools/ui_check.py --check-js
node --check js/tour.js
node --check js/onboarding.js
```

Вторая команда требует Node.js: `node --check` проверяет внедряемый `ui_probe.js`,
константы JS и статические inline-тела из `ui_check.py`. Она не открывает браузер.

После параллельных правок сайта Claude должен запустить сервер и полный прогон:

```powershell
python tools/ui_check.py out=tools/ui-check-results --json
```

Затем разобрать `scenario_errors`, axe violations, список «проверить руками» и
снимки, особенно шторку над картой/графом, возврат поиска, схему корабля,
PhotoSwipe, фокус всех пяти кнопок панели и 200%. Сбой селектора или
изменение данных нужно отличать от дефекта сайта; сценарий не должен молча
подменять недоступный элемент DOM-кликом. В Codex проверен только синтаксис:
Edge здесь не запускался.
